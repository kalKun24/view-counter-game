# 3 UI 仕様

PBI #3「カウントダウンモード」。見た目・文言・画面構成の出典は `.scrum/designs/prototype.html`（以下「試作版」）。この仕様は #4（チャージ）と #5（ハイ＆ロー対戦）が再利用する共通部品を定義するため、共通部品とモード固有を分けて書く。

## 対象画面・コンポーネント
新規（`src/` は未作成。パスは react-specialist が決める）。試作版の `home` / `setupSolo` / `play` / `end` を React に移植し、再生回数の取得を手入力から API 自動取得に置き換える。

画面は4つ。画面遷移は状態管理のみで、URL ルーティングは使わない。

1. ホーム
2. 難易度設定（カウントダウン用。チャージも #4 で共用する）
3. プレイ
4. 結果

### 共通部品とモード固有の分担
共通部品は #3 で実装し、#4・#5 は改造せず props で差し替える。#4・#5 が共通部品の外側に変更を要する場合は、その PBI の仕様で差分を書く。

| 部品 | 区分 | 役割 | モードごとに差し替える点 |
|---|---|---|---|
| AppShell | 共通 | `.wrap`（最大幅560px、1カラム、gap 16px）とテーマ変数 | なし |
| ScreenTop | 共通 | 左に戻る系ボタン（`← 戻る` / `やめる`）、右にモード名（eyebrow 見た目の h1） | ボタン文言、モード名 |
| ModeButton / ModeList | 共通 | ホームの3モードボタン | 有効/準備中の切替（下記） |
| Home | 共通 | 見出し、例のカウンター、ModeList、共通ルール | なし |
| DifficultyPicker | 共通 | 難易度の3択（`.seg`）と `LEVELS` の読み出し | クリア条件の1行（モード固有） |
| LEVELS / jp / comma / rand / normWords | 共通（ロジック） | 試作版と同値。`parseViews` と `ytLink` は移植しない | なし |
| Counter | 共通 | 暗い背景の大きい数字表示（label / num / sub / 任意で bar） | label、num、sub、bar の中身 |
| SearchForm | 共通 | 検索入力、決定ボタン、FetchStatus | なし（送信後の処理は onResult で受ける） |
| FetchStatus | 共通 | 取得中・エラー・重複などのメッセージと再試行ボタン | なし |
| WordLog | 共通 | 履歴の一覧 | 符号（`−` / `+` / なし）、`who`（#5） |
| ResultBanner / ResultActions | 共通 | 結果の見出し・理由・詳細、「もう一回」「モード選択へ」 | 見出し文字（CLEAR / GAME OVER / GAME SET）、理由、詳細 |
| 取得フック（useViewsFetch） | 共通（ロジック） | `GET /api/views?q=` の呼び出し、結果の分類、二重送信防止、使用済み判定 | なし |
| カウントダウンの判定 | モード固有（#3） | 引き算、アウト/クリア/ターン切れの順序判定 | #4・#5 は別の判定を持つ |

SearchForm の onResult は次の3種を受ける。モードはこれだけで判定できる。

- `found`：`{ query, viewCount, title, videoId }`（viewCount は API の正しい値）
- `nomatch`：`{ query }`
- （通信失敗と q 不正は FetchStatus が処理し、モードには渡さない）

WordLog の1行のデータ：`{ query, truncated, actual, title, who? }`。truncated は切り捨て値、actual は API の正しい再生回数。

## 構成

### 共通の見た目
試作版の CSS 変数・フォント・角丸・余白をそのまま引き継ぐ（`--bg` `--panel` `--ink` `--muted` `--line` `--accent` `--counter-bg` `--counter-fg` `--bad`、ライト/ダーク両対応、`prefers-reduced-motion` 対応）。ダークモードは OS 設定に従い、切替ボタンは作らない。次の3点だけ試作版から変える（理由は「仮定」）。

- 入力欄の文字サイズを 16px にする（iOS Safari の自動ズーム防止）。
- ボタン・難易度ボタン・モードボタンの高さを 44px 以上にする。
- ライトモードの文字付きオレンジ要素（`.btn` の背景、`.mode .tag` の文字）に `--accent-strong: #c2410c` を使う。`--accent`（#e2671b）は枠線・フォーカスリング・バー等の装飾に残す。ダークモードは `--accent` のまま。

### 1. ホーム
```
header
  eyebrow「YOUTUBE 再生回数ゲーム」
  h1「再生回数カウンター」
  説明文
Counter（例。aria-label="例"）
ModeList
  ModeButton カウントダウン（有効）
  ModeButton チャージ（#4 実装まで準備中）
  ModeButton ハイ＆ロー対戦（#5 実装まで準備中）
panel「共通ルール」（ol）
```
- ホームの例の Counter は試作版のまま固定表示（487,215,330 / 4億8721万5330 回 ／ 残り5ターン）。bar は無し。
- ModeButton は `.mode`（tag、題、説明）。本物の `<button type="button">` を使う。

準備中のモードの見せ方（#3 時点でのチャージ・ハイ＆ロー対戦）
- ボタンは残す（3モードの全体像が見えるため）。tag の右に「準備中」を足す（例：「ソロ・増やす ・ 準備中」）。
- 見た目は `opacity:.55`、枠線を破線にする。押しても何も起きない。
- `aria-disabled="true"` を付け、`disabled` 属性は使わない（キーボードで到達でき、読み上げで「準備中」が分かるため）。クリック・Enter・Space は無視する。
- 有効/準備中は、モードごとの定数（`enabledModes`）1か所で切り替える。#4 と #5 は自分のモードを有効にするだけでよい。

共通ルール（試作版から、手入力と YouTube リンクの手順を除いて書き換える）
1. 検索ワードを入れて「決定」を押す（スペース区切りで複数可）。
2. タイトルに検索ワードが**全部**入っている動画の中で、一番再生回数が多いものの回数を、自動で取得する。
3. 判定には、再生回数の10,000未満を切り捨てた値を使う（例：1,234,567回は1,230,000回）。正しい再生回数は履歴に表示される。
4. 同じワードの組み合わせは2回使えない。語順、大文字と小文字、全角と半角の違いは同じとみなす。

### 2. 難易度設定
```
ScreenTop［← 戻る］［カウントダウン（h1）］
panel
  h2「難易度」
  DifficultyPicker（やさしい / ふつう / むずかしい）
  ul.rules
    お題：{jp(min)} 〜 {jp(max)} 回のあいだでランダム
    ターン数：{turns}
    クリア条件：残りがお題の {tol*100}% 以下（0未満はアウト）  ← カウントダウン固有
  button.btn「お題を引く」
```
LEVELS（試作版と同値。受け入れ基準 1）

| 難易度 | キー | ターン数 | お題の範囲（min 以上 max 未満の整数乱数） | 許容幅 |
|---|---|---|---|---|
| やさしい | easy | 6 | 100,000,000 〜 300,000,000 | 0.05 |
| ふつう | normal | 5 | 300,000,000 〜 1,000,000,000 | 0.02 |
| むずかしい | hard | 4 | 1,000,000,000 〜 5,000,000,000 | 0.005 |

- 初期選択は「ふつう」。選択は `localStorage` のキー `vc-prefs` に `level` として保存し、次回起動時に復元する（試作版と同じ。#5 が `dir` と `players` を同じキーに足す）。読み書き失敗は無視する。
- 表示される許容幅は 5% / 2% / 0.5%。
- お題の範囲は上の表のまま（試作版と同値）。実際のお題は、範囲で引いた値の10,000未満を切り捨てた値で、常に10,000の倍数になる。ルール表示の範囲は切り捨て前の範囲を出す。

### 3. プレイ
```
ScreenTop［やめる］［カウントダウン（h1）］
Counter（カウントダウン用）
  label「のこり ・ お題 {jp(target)}」
  num   {comma(remaining)}
  sub   「{jp(remaining)} 回」 ／ 「残り{left}ターン」
  bar   進捗と許容幅の目印（aria-hidden）
panel（SearchForm。form 要素）
  label「検索ワード（スペース区切りで複数可）」
  input
  button.btn「決定」
  FetchStatus（常に存在する live 領域）
panel「履歴」（WordLog。1行以上あるときだけ表示）
```
Counter の中身
- remaining の初期値はお題。num は `comma(remaining)`、sub 1行目は `jp(remaining) 回`、sub 末尾は `残り{turnsMax - 履歴の行数}ターン`。
- bar：`i` の幅は `max(0, remaining/target*100)%`、`u`（赤い目印）は左から `tol*100`%。幅の変化は `.4s`（reduced-motion では無し）。

WordLog の1行（古い順に上から下。試作版と同じ並び）
```
li
  [01]  検索ワード（太字でなく通常。複数語はそのまま）        −123万
        一致した動画のタイトル（muted・小・文字のみ）
        実際の再生回数 1,234,567 回（muted・小）
```
- グリッドは `2.2em 1fr auto`、gap 8px。左列（番号）、中央列（ワード、タイトル、注釈の3段）、右列（切り捨て値）。
- 右列は `{符号}{jp(切り捨て値)}`（カウントダウンは `−`）。等幅フォント、右寄せ。切り捨て値が0のときは `−0` と表示する。
- 注釈は `実際の再生回数 {comma(actual)} 回`。YouTube の規約上、API の正しい値を注釈として必ず出す（受け入れ基準の指定）。
- タイトルは文字のみ。サムネイル、画像、リンクにしない。React のテキストノードとして出す（HTML として解釈しない）。長いタイトルは折り返す（`overflow-wrap:anywhere`、行数制限なし）。
- タイトルに双方向制御文字（U+202E など）が含まれていても、除去はしないが、タイトルの要素に `unicode-bidi:isolate` を付けて周囲の表示を乱さないようにする。仕様ファイルにはこれらの文字を直接書かない。
- 検索ワードも同様にテキストノードとして出す。

360px 幅の確認
- `.wrap` の左右余白16px、panel の余白16px のため、履歴の内側は約296px。右列は `auto`（最長でも `−49億9999万` 程度）で収まり、中央列が `min-width:0` で縮む。
- Counter の num は `clamp(1.6rem, 8vw, 2.6rem)`（360pxで約28.8px）。最大13桁の等幅表示が約296pxに収まる。超えた場合は `overflow-wrap:anywhere` で折り返す。ページ全体に横スクロールを出さない（`body` と `.wrap` に固定幅を置かない）。

```
ResultBanner（.counter）
  label「結果」
  h1 「CLEAR」または「GAME OVER」（クリアは緑 #45c98a、アウトは赤 #ff6b73。文字でも区別できる）
  sub  理由

.row［もう一回］［モード選択へ］
```

### ゲーム全体

| 難易度設定 | 難易度設定画面 | ホームで「カウントダウン」、結果で「もう一回」 |

### 検索フォーム（プレイ中）
FetchStatus の外側要素に `data-state` を付ける（値は下表の「data-state」）。

| 状態 | data-state | 入力 | 決定ボタン | FetchStatus の表示 | 遷移条件 |
|---|---|---|---|---|---|
| 待機・入力が空 | idle | 空（空白のみを含む） | 無効（`disabled`） | 空 | 初期、成功後（入力を空に戻す） |
| 待機・入力あり | idle | 入力あり | 有効 | 空 | 入力の `trim()` が1文字以上 |
| 取得中 | loading | 読み取り専用（`readOnly`、値は保持） | 無効 | 「取得中…」 | 送信（下記の事前チェックを通過） |
| 重複 | duplicate | 入力を保持 | 有効 | 「そのワードの組み合わせはもう使われています。」（`.msg.bad`） | 事前チェックで使用済み。API は呼ばない |
| 通信失敗 | error | 入力を保持（編集可） | 有効 | エラーメッセージと「もう一度試す」ボタン | ネットワーク断、タイムアウト、5xx（502 を含む）、不正な応答 |
| q 不正 | invalid | 入力を保持 | 有効 | 「このワードでは検索できません。別のワードを入れてください。」（`.msg.bad`。再試行ボタンは出さない） | 400 `invalid_query` |
| 該当あり（一瞬） | - | 空に戻す | - | 空 | 200 `found:true`。判定へ進む |
| 該当なし（一瞬） | - | - | - | - | 200 `found:false`。結果画面（GAME OVER）へ |

- 履歴が0行のとき、履歴の panel は出さない（空状態は「何も出さない」）。
- 重複・通信失敗・q 不正のメッセージは、入力を変えたとき、または次の送信を始めたときに消す。ただし再試行ボタン経由の再送は、入力が変わっていなくても同じクエリを使う。
- 通信失敗・q 不正・重複では、ターン、使用済みワード、残りを一切変えない。

### 取得結果の分類（受け入れ基準 2・6・9）
| 応答 | 分類 | 扱い |
|---|---|---|
| 200 `{found:true, viewCount, video:{id,title}}` | found | 判定へ。使用済みに追加 |
| 200 `{found:false}` | nomatch | GAME OVER（履歴には追加しない。理由にワードを出す） |
| 400 `invalid_query` | invalid | 「q 不正」状態。使用済みにしない |
| 5xx（502 `upstream_error`、503 を含む） | error | 「通信失敗」状態。使用済みにしない |
| ネットワーク断、15秒で応答なし、JSON として読めない、found でも viewCount/title が欠ける | error | 同上 |

503（クォータ切れ）は #10・#11 で専用表示にする。それまでは他の 5xx と同じ「通信失敗」で表示する。

### 判定（カウントダウン固有。受け入れ基準 3・7）
found を受けたら、次の順で行う（試作版と同じ）。

1. `truncated = floor(viewCount / 10000) * 10000`（例：1,234,567 → 1,230,000。9,999以下は 0）。
2. 使用済みワードに正規化キーを追加。履歴に `{query, truncated, actual: viewCount, title}` を追加。
3. `remaining = remaining - truncated`。
4. `remaining < 0` ならアウト（理由「0を割ってしまった！」）。
5. そうでなく `remaining <= target * tol` ならクリア（理由「ゴール圏に到達！」）。
6. そうでなく 履歴の行数 `>= turnsMax` ならアウト（理由「ターン切れ。」）。
7. いずれでもなければプレイ継続。入力を空にして入力欄へフォーカスを戻す。

残り表示は、常に切り捨て値から計算した `remaining` だけを使う（正しい再生回数は残りの計算に使わない）。

nomatch は GAME OVER。理由は「条件に合う動画が見つかりませんでした。（ワード：{検索ワード}）」。残りと履歴は直前のまま（ターンは増えない）。

## 操作
| 操作 | 結果 | 失敗時の表示 |
|---|---|---|
| ホームで「カウントダウン」を押す | 難易度設定へ | なし |
| ホームで準備中のモードを押す | 何も起きない（`aria-disabled`） | なし |
| 難易度ボタンを押す | `aria-pressed` が切り替わり、下のルール表示が更新される。`vc-prefs` に保存 | 保存失敗は無視 |
| 「お題を引く」を押す | `rand(min, max)` で引いた値の10,000未満を切り捨てて（`floor(n / 10000) * 10000`）お題を決め、プレイ画面へ。履歴と使用済みは空 | なし |
| 「← 戻る」を押す | ホームへ | なし |
| 「やめる」を押す | 確認なしでホームへ。取得中ならリクエストを中止し、結果は捨てる | なし |
| 検索入力に文字を入れる | 入力が空でなければ「決定」が有効になる。エラー/重複/q 不正のメッセージを消す | なし |
| 「決定」を押す、または入力欄で Enter | 下の送信手順を実行 | 下表 |
| 「もう一度試す」を押す | 失敗したクエリで送信手順の取得部分をやり直す（事前チェックは通過済みのため省略） | 再び失敗すれば同じ表示 |
| 結果で「もう一回」 | 難易度設定へ | なし |
| 結果で「モード選択へ」 | ホームへ | なし |

送信手順
1. 取得中、または入力の `trim()` が空なら何もしない（受け入れ基準 8・10。ボタンが無効でも Enter 経路で二重に守る）。
2. 事前チェック：入力を `NFKC` 正規化 → 小文字化 → 半角/全角スペースで分割 → 空要素を除去 → 並べ替え → 半角スペースで連結、したキーが使用済みなら「重複」状態にして終了（API を呼ばない）。
3. 状態を「取得中」にして、`GET /api/views?q=<trim した入力をエンコード>` を呼ぶ。
4. 応答を分類して上の表のとおりに進める。

試作版の `normWords` は `toLowerCase` と空白分割だけだったため、全角英数を同一視するために `NFKC` を先に掛けるのが試作版からの唯一のロジックの追加である（受け入れ基準 5 の「全角と半角」を満たすため）。

| 失敗 | 表示 | 状態の変化 |
|---|---|---|
| 通信失敗 | 「取得に失敗しました。通信を確かめて、もう一度試してください。」と「もう一度試す」ボタン。補足に「ターンは減っていません。」 | なし |
| q 不正 | 上記 | なし |
| 重複 | 上記 | なし |
| 入力が空 | 表示なし（ボタンが無効のため操作自体ができない） | なし |

## アクセシビリティ
- 構造：各画面に h1 を1つだけ置く。ホームは「再生回数カウンター」、難易度設定とプレイは ScreenTop のモード名、結果は「CLEAR」「GAME OVER」。panel の見出しは h2。`document.title` は「再生回数カウンター」。
- フォーカス移動
  - 画面を切り替えたら、その画面の h1 に `tabindex="-1"` でフォーカスを移す。ただしプレイ画面は検索入力にフォーカスする。
  - 成功して継続するとき、通信失敗・重複・q 不正の後は、検索入力にフォーカスを戻す（再試行ボタンを押した後に取得中へ入る場合は、ボタンが消えるためフォーカスを入力欄へ移す）。
  - 取得中に押せなくなる「決定」ボタンからフォーカスを失わせない（`disabled` にする前後でフォーカスを入力欄に置く）。
- キーボード：すべての操作は Tab / Enter / Space で行える。検索入力は `<form>` 内に置き、Enter で送信する。`enterkeyhint="go"`、`autocomplete="off"`、`autocapitalize="off"`、`spellcheck="false"`、`type="text"`。
- ラベル：検索入力は `<label for>` と対応させる。難易度の `.seg` は `role="group" aria-label="難易度"`、各ボタンは `aria-pressed`。ホームの例の Counter は `aria-label="例"`。
- 読み上げ
  - FetchStatus は `role="status"`（`aria-live="polite"`）。取得中・重複・q 不正はこの領域の文言が読まれる。通信失敗のみ `role="alert"` にする。
  - 検索入力は取得中 `aria-busy="true"`。
  - 継続時の結果を読み上げるため、視覚的に隠した `role="status"` に「{jp(truncated)} を引いて、残り {jp(remaining)}。残り{left}ターン。」を出す。
  - bar は `aria-hidden="true"`（数値で同じ情報を出すため）。
  - 履歴は `<ul>`。数字だけの右列は、そのままで読み上げ可能にする（符号は U+2212）。
- コントラスト：本文は試作版のトークンのまま。ライトモードのオレンジ文字と、白文字のオレンジ背景ボタンは、試作版の #e2671b では約3.4:1 で AA に届かない。`--accent-strong` #c2410c（白に対して約5.2:1）に置き換える。CLEAR / GAME OVER は暗い背景に緑/赤で、文字の違いでも判別できる。
- タッチ：ボタンと入力は高さ44px以上、隣り合う操作の間隔は8px以上。入力の文字は16px。
- フォーカス表示：試作版の `outline:3px solid var(--accent); outline-offset:2px` を維持する。
- 動き：`prefers-reduced-motion` では bar の `transition` を止める。
- 外部通信：Google Fonts は試作版どおり `<link>` で読む。失敗してもフォールバックのフォントで表示できる。

## 受け入れ基準との対応
| 受け入れ基準 | 満たす要素 |
|---|---|
| 難易度ごとのターン数・お題の範囲・許容幅が `LEVELS` と一致。お題は10,000未満を切り捨てた値 | 「構成 2」の LEVELS 表と切り捨ての注記、「お題を引く」の操作、`level-*`、`rule-range` `rule-turns` `rule-clear` |
| 検索ワードを入れると API から再生回数を取得し、お題から引く | SearchForm の送信手順、取得結果の分類（found）、判定の手順 3 |
| 判定の再生回数は10,000未満切り捨て、残りも切り捨て値から計算 | 判定の手順 1・3、`counter-value`、`log-value` |
| 履歴の各行にワード、切り捨て値、正しい再生回数（注釈）、動画タイトル（文字のみ）。サムネイルなし | WordLog の1行、`log-word` `log-value` `log-actual` `log-title` |
| 同じワードの組み合わせは1ゲームで2回使えない。使用済みにするのは取得成功のとき | 送信手順の事前チェック（NFKC、小文字、分割、並べ替え）、重複状態、判定の手順 2（found のときだけ追加）、失敗時は追加しない |
| 条件に合う動画が無いときは GAME OVER | 取得結果の分類（nomatch）、結果画面、`result-heading` |
| 判定は 0未満でアウト、許容幅以下でクリア、ターン切れでアウトの順 | 判定の手順 4〜6 |
| 取得中は決定ボタンを無効にし「取得中…」を表示。二重送信不可 | 状態「取得中」、送信手順 1、`search-submit`、`loading-message` |
| 通信失敗ではメッセージと再試行ボタン。ターンと使用済みワードを消費しない | 状態「通信失敗」、`error-message`、`retry-button`、「失敗時の状態変化はなし」 |
| 入力が空のときは送信しない | 状態「入力が空」（ボタン無効）、送信手順 1 |
| 幅360pxで横スクロールが出ない | 「プレイ」の360px幅の確認、固定幅を置かない規則 |
| 見た目は試作版を引き継ぐ。手入力欄・「YouTubeで探す」・`parseViews` は移植しない。`jp` と `comma` は移植する | 「共通の見た目」、共通ルールの書き換え、「文言」の数字表示 |

## 仮定
- 準備中のモード：ホームに3モードのボタンを並べ、#4・#5 が未実装の間は「準備中」の表示と `aria-disabled` で押せなくした。非表示や、押したときのエラー表示にはしなかった。全体像が見えることと、スマホで押して迷わないことを優先した。
- nomatch の扱い：found:false は「取得に成功した」とも言えるが、ゲームが終わるため使用済みへの追加は意味を持たない。履歴にも追加せず（動画もワード以外の値もない）、理由にワードを出す。ターンも増やさない（その場で終了するため）。
- 重複チェックは API を呼ぶ前に行う（クォータの節約のため）。受け入れ基準の「使用済みにするのは取得に成功したとき」は、使用済みへの追加のタイミングのみを指し、事前の照合を禁じていない、と解釈した。
- 正規化：試作版の `normWords` に、先頭で `NFKC` 正規化を足す。全角英数・全角スペースの同一視は、受け入れ基準 5 の指定だが、試作版は小文字化と空白分割だけでは全角英数を同一視できないため。
- API へは、`trim` しただけの入力をそのまま送る（正規化したキーは送らない）。検索ワードの長さ制限・連打制限は #7 の範囲で、この PBI では置かない。
- 15秒でクライアント側のタイムアウトとし、通信失敗として扱う。取得が返らないとき、操作できる状態に戻すため。値は変えてよい。
- 503（クォータ切れ）は、#10・#11 まで通常の通信失敗と同じ表示にする。
- 通信失敗の「もう一度試す」は、入力欄の現在の値でなく、失敗したクエリを再送する。ただし入力を変えるとエラーごと消えるため、実際には両者は一致する。
- お題の切り捨て：PO の指摘（Sprint 2 デモ）で、お題も再生回数と同じく10,000未満を切り捨てる。範囲は試作版のまま。クリア判定の `target * tol` は切り捨て後のお題で計算する。
- 切り捨て値が0の行（9,999回以下）は右列を `−0` と表示する。残りは変わらず、ターンは消費する。
- 双方向制御文字（U+202E など）を含むタイトルは、除去せず `unicode-bidi:isolate` で表示を閉じ込める。動画タイトルは外部由来の文字列のため、HTML として解釈しない（React のテキストノード）ことも前提にしている。
- 戻る/進むなどブラウザの履歴操作は扱わない（URL ルーティング無し。リロードでホームに戻る）。ゲーム途中のリロードでの復元もしない。
- ライトモードの `--accent-strong` と、入力 16px、44px 以上のタップ領域は、「見た目は試作版を引き継ぐ」の例外。トレードオフスライダーの「品質（スマホでの操作のしやすさ）」を優先し、色相は変えていない。
- ダークモードは試作版どおり OS 設定に従うだけで、切替ボタンは作らない。
- 履歴は古い順（試作版と同じ）。長いゲームでも最大6行のため、折りたたみやスクロール制御は要らない。
