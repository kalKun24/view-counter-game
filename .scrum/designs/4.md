# 4 UI 仕様

チャージモード。共通部品は #3 の仕様に任せ、この仕様はチャージ固有の部分だけを定める。見た目と文言は試作版（`.scrum/designs/prototype.html`）の `counterHTML` のチャージ部分、`setupSolo` のクリア条件、`end` の detail を引き継ぐ。

## 対象画面・コンポーネント
- 新規：チャージ用のカウンター表示（合計、目標と上限、バー）。
- 新規：チャージの結果の判定と、結果画面の detail。
- 既存の変更：#3 の仕様の〈難易度設定〉のクリア条件の行。モードがチャージのときだけ、下記「文言」の行にする。
- 共通部品（#3 の仕様に任せる）：〈ホーム〉、〈難易度設定〉の骨格、〈カウンター表示〉の枠（`.counter`）、〈検索入力〉、〈取得中・エラー表示〉、〈履歴〉、〈結果画面〉の骨格。
- 実装先のファイルパスは #3 の実装で決まるため、この仕様では定めない。

## 構成
画面は 〈ホーム〉→〈難易度設定〉→ プレイ画面 → 〈結果画面〉 の順に進む。チャージ固有の箇所だけを書く。

### 難易度設定（チャージ）
- 見出しの横の eyebrow は「チャージ」。
- 難易度の切り替え、お題の範囲、ターン数の行は #3 の仕様の〈難易度設定〉のまま。値は下表（試作版の `LEVELS` と同じ）。
- クリア条件の行は、チャージ用の文言にする。
- ボタンは #3 の〈難易度設定〉の「お題を引く」と同じ位置・同じ見た目。押すと目標を範囲内の整数でランダムに引いて10,000未満を切り捨て、合計 0 でプレイ画面に進む。

| 難易度 | ターン数 | 目標の範囲 | 許容幅 | クリア条件の行の表示 |
|---|---|---|---|---|
| やさしい | 6 | 1億 〜 3億 | 5% | 目標以上、かつ目標の 105% 以下（超えたらバースト） |
| ふつう | 5 | 3億 〜 10億 | 2% | 目標以上、かつ目標の 102% 以下（超えたらバースト） |
| むずかしい | 4 | 10億 〜 50億 | 0.5% | 目標以上、かつ目標の 100.5% 以下（超えたらバースト） |

### プレイ画面
上から順に、次を並べる。1 列、最大幅 560px は #3 の仕様に従う。
1. 上段：「やめる」ボタンと eyebrow「チャージ」（#3 の仕様のまま）。
2. チャージのカウンター（`.counter`、`data-testid="charge-counter"`）。中身は次の順。
   1. ラベル行（`data-testid="charge-label"`）：`合計 ・ 目標 {目標の日本語表記} 〜 上限 {上限の日本語表記}`
   2. 合計（`data-testid="charge-total"`）：現在の合計を桁区切りで表示する。大きな数字（`.num`）。
   3. 補助行（`data-testid="charge-sub"`）：`あと {不足分の日本語表記} 回 ／ 残り{残りターン}ターン`
   4. バー（`data-testid="charge-bar"`）：下記。
3. 〈検索入力〉（#3 の仕様のまま）。
4. 〈取得中・エラー表示〉（#3 の仕様のまま）。
5. 〈履歴〉（#3 の仕様のまま。1 行ごとの値の書き方だけ下記）。

### 各表示の計算
- 目標：難易度の範囲で引いた整数の10,000未満を切り捨てた値（`floor(n / 10000) * 10000`）。
- 上限：目標 ×（1 + 許容幅）の10,000未満を切り捨てた値。表示も判定もこの切り捨て後の値を使う。常に10,000の倍数になる。
- 合計：各ターンの再生回数を 10,000 未満で切り捨てた値の総和。0 から始める。
- 不足分：max(0, 目標 − 合計)。合計が目標以上になる前に判定で終わるので、プレイ中は常に 1 以上になる。
- 残りターン：ターン数 − 履歴の件数。

### バー
- 試作版のバーを引き継ぐ。高さ 8px、角丸、背景は薄い白、塗りは `--counter-fg`。
- 塗りの幅：min(100, 合計 ÷ 上限 × 100) %。塗りの要素は `data-testid="charge-bar-fill"` を持ち、幅の値を `data-percent`（小数 1 桁）として持つ。
- 目標線：赤い縦線（2px、バーより上下に 3px はみ出す、色 `--bad`）を、左から 目標 ÷ 上限 × 100 % の位置に置く。要素は `data-testid="charge-bar-target"`。
- 塗りの幅は 0.4 秒で変化する。`prefers-reduced-motion` のときは即時（#3 の仕様の共通方針に従う）。
- バーは装飾として `aria-hidden="true"` にする。同じ情報は合計と補助行の文字で読み上げられる。

### 履歴の 1 行（チャージ分）
- 右端の値：`+{切り捨て後の値の日本語表記}`。切り捨て後が 0 のときは `+0`。
- 正しい再生回数（注釈）と動画タイトルの並べ方は #3 の仕様の〈履歴〉と同じ形にする。チャージでは符号だけが違い、`−` の代わりに `+` を使う。

### 結果画面（チャージ）
〈結果画面〉の骨格は #3 の仕様のまま。チャージ固有は次の 3 点。
1. 見出し（`data-testid="result-heading"`）：クリアなら `CLEAR`（`--good` 系の緑）、それ以外は `GAME OVER`（`--bad` 系の赤）。
2. 理由（`data-testid="result-reason"`）：下記「文言」の判定ごとの文。
3. detail（`data-testid="result-detail"`）：`合計 {合計を桁区切り} 回（目標の {合計 ÷ 目標 × 100、小数 1 桁}%）・{履歴の件数}ターン`。中央寄せ、`.muted`。
- 結果画面にも履歴を出す（#3 の仕様のまま）。
- 「もう一回」は〈難易度設定〉（チャージ）に戻る。「モード選択へ」は〈ホーム〉に戻る。

## 状態
| 状態 | 表示 | 遷移条件 |
|---|---|---|
| 設定中 | 〈難易度設定〉（チャージ）。クリア条件の行がチャージ用。 | ホームでチャージを選ぶ。「もう一回」。 |
| プレイ中（初期） | 合計 0、あと {目標} 回、残り{ターン数}ターン、バーは 0%、履歴なし（履歴の枠も出さない）。 | 「お題を引く」を押す。 |
| プレイ中（途中） | 合計、不足分、残りターン、バーが更新される。履歴が増える。 | 決定した結果の判定が、バースト・クリア・ターン切れのどれでもない。 |
| 取得中 | #3 の仕様の〈取得中・エラー表示〉のとおり（「取得中…」、ボタン無効化）。合計・残りターン・バーは変わらない。 | 決定を押す。 |
| 通信エラー | #3 の仕様のとおり（エラーと再試行）。合計・残りターン・履歴は変わらない。使用済みワードにも入れない。 | API が 400・502・通信失敗を返す。 |
| 使用済みワード | #3 の仕様のとおり（拒否メッセージ）。ターンも合計も進まない。 | 同じワードの組み合わせ（語順・大文字小文字・全角半角の違いは同じとみなす）を入れる。 |
| 該当なし | `GAME OVER`。理由は #3 の仕様の文言。detail はその時点の合計で出す。 | API が `{"found":false}` を返す。 |
| 結果：クリア | `CLEAR`。理由「目標ラインに到達！」。 | 合計が上限以下、かつ目標以上（バーストでない）。 |
| 結果：バースト | `GAME OVER`。理由「上限を超えてバースト！」。 | 合計が上限を超えた。 |
| 結果：ターン切れ | `GAME OVER`。理由「ターン切れ。」。 | バーストでもクリアでもなく、履歴の件数がターン数に達した。 |

### 判定の順序
1 回の取得に成功して合計を更新するたびに、次の順で判定する。最初に当てはまったもので終わる。
1. 合計 > 上限 → バースト（`GAME OVER`）。
2. 合計 ≥ 目標 → クリア（`CLEAR`）。
3. 履歴の件数 ≥ ターン数 → ターン切れ（`GAME OVER`）。
4. いずれでもなければ次のターンへ。

### 境界値
- 合計がちょうど目標：クリア。
- 合計がちょうど上限：バーストではなくクリア（「上限を超えたら」バースト）。
- 合計が上限より 1 大きい：バースト。
- 最終ターンで、合計がちょうど目標に届いた：ターン切れより先にクリア。
- 最終ターンで、合計が上限を超えた：ターン切れより先にバースト。
- 切り捨て後の値が 0（10,000 未満）：合計は変わらないが、ターンは 1 つ減る。

## 文言
- 〈ホーム〉のチャージのカード（試作版のまま）：タグ「ソロ・増やす」、名前「チャージ」、説明「0から再生回数を足していき、ターン内に目標ラインへ。上限を超えたらバースト。」
- 難易度設定のクリア条件の行：`クリア条件：目標以上、かつ目標の {100 + 許容幅×100}% 以下（超えたらバースト）`
- カウンターのラベル：`合計 ・ 目標 {目標} 〜 上限 {上限}`（日本語表記は「1億2345万」のように、億・万を使う）
- カウンターの補助行：`あと {不足分} 回 ／ 残り{N}ターン`
- 履歴の値：`+{値}`
- 結果の見出し：クリアは `CLEAR`、それ以外は `GAME OVER`
- 結果の理由：
  - クリア：`目標ラインに到達！`
  - バースト：`上限を超えてバースト！`
  - ターン切れ：`ターン切れ。`
  - 該当なし：#3 の仕様の文言（この仕様では定めない）
- 結果の detail：`合計 {合計} 回（目標の {割合}%）・{N}ターン`
- 取得中、通信エラー、使用済みワードのメッセージ：#3 の仕様の文言（この仕様では定めない）

## アクセシビリティ
- キーボード操作、フォーカスの見た目（3px のアクセント色の枠）、入力のラベルは #3 の仕様のとおり。チャージ固有の操作は無い。
- 判定が続行になったときは、フォーカスを検索欄に戻す（試作版と同じ）。
- 結果画面に切り替わったときは、結果の見出しにフォーカスを移すか、読み上げ領域（`role="status"`）で見出しと理由を読み上げる。方法は #3 の仕様に合わせる。
- 合計・補助行は文字で読めるので、バーは `aria-hidden="true"`。目標線の位置は文字（ラベル行）で伝わる。
- 結果の色（緑・赤）だけで勝敗を伝えない。`CLEAR` / `GAME OVER` の文字が勝敗を示す。
- コントラスト：カウンターの文字は暗い背景に明るい色（`--counter-fg`）。ダークモードでも同じ。結果の緑・赤はダークモード用の明るい値（`--good`、`--bad` のダーク側）を使う。
- 合計が更新されるたびに読み上げ領域で通知するかは、#3 の仕様の履歴追加の通知に合わせる。この仕様で別の通知を足さない。

## 仮定
- `.scrum/designs/3.md` は、この仕様を書いた時点で存在しない。#3 の共通部品（〈ホーム〉、〈難易度設定〉、〈カウンター表示〉の枠、〈検索入力〉、〈取得中・エラー表示〉、〈履歴〉、〈結果画面〉）は、試作版と同じ見た目・配置で、次のものを定めると想定した。#3 の仕様と食い違う場合は #3 の仕様を優先し、チャージ固有の部分だけをこの仕様に残す。
  - 〈履歴〉の 1 行に、切り捨て値、正しい再生回数（注釈）、動画タイトルが入る。
  - 該当なしのときの理由の文言、使用済みワードの拒否メッセージ、取得中の「取得中…」、通信エラーの文言と再試行。
  - 〈結果画面〉の骨格（`.counter` の見出し、理由、detail、「もう一回」「モード選択へ」、履歴）。
- 結果画面の detail は試作版の書式をそのまま使い、「目標の {割合}%」は小数 1 桁にする（試作版の `toFixed(1)`）。
- 該当なしで終わったときの detail は、その時点の合計と履歴の件数で出す。該当なしのターンは履歴に入れない。
- 切り捨て後が 0 になる再生回数も有効な入力として扱い、ターンを 1 つ消費する。デモ台本 5 のモックのワードは、足す値が 10,000 以上になるものを使う。
- 上限は目標 × （1 + 許容幅）を10,000未満で切り捨てた整数にする（PO の指摘、Sprint 2 デモ）。小数の誤差で境界値がずれないよう、切り捨ても整数どうしの計算で行う（例：許容幅を千分率の整数で持ち、`floor(目標 × (1000 + 千分率) / 1000 / 10000) * 10000` で求める）。判定は `合計 > 上限`。この方法は実装側で決めてよく、境界値のテストで確かめる。
- クリア条件の行の「目標の 105% 以下」などは許容幅の説明であり、実際の上限は切り捨て後の値になる（わずかに低くなりうる）。
- 目標は試作版の `rand(min, max)`（min 以上 max 未満の整数）で引いた値を、10,000未満で切り捨てた値とする。範囲は試作版のまま。
- バーの塗りは上限で頭打ちにする（試作版の `Math.min(100, ...)`）。バースト時は 100% になる。
- バーストの瞬間の合計の表示は、結果画面の detail に出るので、プレイ画面に残さない。
- 不可視文字・制御文字の表示は扱わない。動画タイトルや検索ワードの表示のエスケープは #3 の仕様に従う。
