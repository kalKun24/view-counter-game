# 5 UI 仕様

ハイ＆ロー対戦の固有部分だけを書く。共通部品は #3 の仕様（`.scrum/designs/3.md`）に任せ、「#3 の仕様の〈部品名〉」と呼ぶ。見た目（色・フォント・余白・角丸・ボタン）は試作版（`.scrum/designs/prototype.html`）の CSS 変数とクラス（`.panel` `.counter` `.seg` `.btn` `.chip` `.log` `.msg`）をそのまま使う。

## 対象画面・コンポーネント
すべて新規（Vite の雛形はまだ無いため、ファイルパスは実装者が決める）。試作版の次の部分を React に移植して引き継ぐ。
- 対戦の設定画面：試作版 `setupVs`
- 対戦のプレイ画面：試作版 `play` と `counterHTML` の対戦部分
- 対戦の結果画面：試作版 `end` の対戦部分

新しい部品は次の3つだけである。ほかは #3 の部品を再利用する。
1. 生存者一覧（`.chip` を使う）
2. 手番の引き継ぎカード（`.panel` を使う）
3. 勝者表示（`.counter` を使う）

### #3 の仕様に任せる共通部品
| 部品 | #3 の仕様での名前 | #5 での使い方 |
|---|---|---|
| ホーム | 「#3 の仕様のホーム」 | 「ハイ＆ロー対戦」ボタンから設定画面へ入る。ボタンの見た目と文言は試作版どおり |
| カウンター表示 | 「#3 の仕様のカウンター表示」 | 直前の判定値と手番のラベルを出す。ラベルと数字の中身だけを本仕様で決める |
| 検索入力 | 「#3 の仕様の検索入力」 | 検索ワード入力と決定ボタン。YouTube への別タブリンクと再生回数の手入力は無い |
| 取得中・エラー表示 | 「#3 の仕様の取得中表示」「#3 の仕様のエラー表示」 | 文言・無効化・再試行は #3 と同じ |
| 履歴 | 「#3 の仕様の履歴」 | 1行の形（切り捨て値、正しい再生回数の注釈、動画タイトル）は #3 と同じ。プレイヤー名と脱落印だけ足す |
| 結果画面 | 「#3 の仕様の結果画面」 | 「もう一回」「モード選択へ」と履歴を使う。見出し部分だけ本仕様の勝者表示にする |

## 構成
### 1. 設定画面（`data-testid="vs-setup"`）
上から順に並べる。1カラム、最大幅 560px（試作版の `.wrap`）。
1. 上部バー：`← 戻る`（`vs-back`）と、右に `ハイ＆ロー対戦`（`.eyebrow`）
2. `.panel`「勝ち負けの向き」
   - `.seg` の2択：`前より高く`（`vs-dir-higher`）、`前より低く`（`vs-dir-lower`）。既定は「前より高く」。選んだほうが `aria-pressed="true"`
   - 説明文（`.muted.small`、`vs-dir-help`）。向きで差し替える
3. `.panel`「プレイヤー（2〜8人）」
   - 人数の表示：`現在 N 人`（`vs-player-count`）
   - 名前入力の行を人数分。行ごとに `<input>`（`vs-player-input-0` から連番）と、削除ボタン `×`（`vs-player-remove-0` から連番。人数が2人のときは出さない）
   - 行の下に `＋ 追加`（`vs-add-player`。8人で `disabled`）と `スタート`（`vs-start`）を横並びで置く

### 2. プレイ画面（`data-testid="vs-play"`）
上から順に並べる。
1. 上部バー：`やめる` と、右に `ハイ＆ロー対戦`（`.eyebrow`）
2. 生存者一覧（`vs-survivors`）：登録順に `.chip` を並べて折り返す（8人でも1画面に収まる）。1人分は次の形である。
   - 生存者：`名前`（`vs-survivor-0` から登録順の連番。`data-status="alive"`）
   - 現在の手番：生存者の chip に先頭の `▶` と太字、`accent` 色の枠を付ける（`data-status="current"`）
   - 脱落者：名前に取り消し線を引き、末尾に `脱落` と書く。文字色は `--muted`（`data-status="out"`）
   - 色だけで区別しない。`▶`・取り消し線・`脱落` の文字で区別する
   - 見出しは付けず、一覧の前に `.eyebrow` で `のこり N 人 / 全 M 人`（`vs-alive-count`）を出す
3. カウンター表示（#3 の部品を使い、`vs-counter` を付ける）
   - ラベル：`{名前} の番 ・ {条件}`（`vs-current-player` は名前だけを入れた要素）
   - 数字：直前の判定値（切り捨て後）を `comma`、下の行に `jp` を出す。最初の1手（higher）は `—`
   - 条件の文言は「文言」節を参照
4. 次のどちらか1つ（同時には出さない）
   - 検索入力（#3 の部品）：手番の人が入力する通常の状態
   - 手番の引き継ぎカード（`vs-handoff`）：直前の手の結果を知らせ、次の人へ渡す状態
5. 履歴（#3 の部品）。1手ごとに1行。脱落した手は末尾に `脱落` の印を付ける（`vs-log-out`）

### 3. 手番の引き継ぎカード（`vs-handoff`）
`.panel`。手が終わるたび（ゲームが続くとき）、検索入力の代わりに出す。
- 結果の1行（`vs-handoff-result`）：直前のプレイヤーの結果。成功と脱落で色を変える（`--good`／`--bad`）。文字でも区別する
- 補足の1行（`vs-handoff-note`）：脱落かつ条件に合う動画が無かったときだけ `直前の数字はそのまま` を出す
- 次の人の案内（`vs-handoff-next`）：`次は {名前} さん。スマホを渡してください。`
- 大きな主ボタン（`vs-handoff-go`）：`{名前} です。始める`（高さ 48px 以上、幅いっぱい）

このカードを置く理由：1台のスマホを回す遊びなので、脱落や成功を全員が見てから渡せるようにする。前の人の入力欄が残ったまま次の人に渡る誤操作も防ぐ。

### 4. 結果画面（`data-testid="vs-result"`）
1. 勝者表示（`vs-winner`）：`.counter` 形式
   - ラベル（`.label`）：`決着`
   - 大きな数字の位置（`.num`、`--counter-fg`）：`GAME SET`
   - その下（`vs-winner-name`）：`{名前} の勝ち！`（Dela Gothic One、1.6rem 相当、中央寄せ）
   - 理由（`vs-winner-reason`、`.jp`）：「文言」節を参照
2. 生存者一覧（プレイ画面と同じ部品。勝者は `data-status="winner"` とし、先頭に `🏆` ではなく文字 `勝` を付ける。ほかは脱落表示のまま）
3. 補足（`.muted` 中央寄せ、`vs-result-turns`）：`{N}手つづきました`
4. `もう一回`（`vs-again`）と `モード選択へ`（`vs-home`）。#3 の結果画面と同じ位置
5. 履歴（#3 の部品）

| 決着・最後の1人 | 結果画面。勝者は残った1人。理由は `最後の1人まで生き残った！` | 脱落の結果、生存者が1人になる。引き継ぎカードは出さず、すぐ結果画面へ |
| 決着・0ちょうど | 結果画面。勝者は0を出した人。理由は `{判定値}（0）ちょうど！ その場で勝ち！`（実際の文は「文言」節） | 判定値が0ちょうどで、その手が負けではない。残りの人数は問わない。引き継ぎカードは出さない |

### 手番の進め方
- 手番は登録順に回す。次の人は、現在の人の次から順に見て、最初に見つかる生存者である。末尾の次は先頭に戻る。脱落者は飛ばす。
- 脱落した手でも、手番は脱落者の次の生存者に進む。
- 「前の値」は、成功した手の判定値だけを更新する。脱落した手（負けも該当なしも）は更新しない。

### 判定の順序（1手ごと）
1. ワード重複を調べる（重複なら手番を進めずに終わる）
2. API を呼ぶ（エラーなら手番を進めずに終わる。ワードは使用済みにしない）
3. 該当なしなら脱落（前の値は更新しない）
4. 判定値＝再生回数を10,000未満で切り捨てた値。前の値（または lower の最初のお題）と比べ、負けなら脱落
5. 負けでなく、判定値が0ちょうどなら、その場で勝ち
6. それ以外は成功。前の値を更新する
7. 脱落の結果、生存者が1人になれば、その人の勝ち

## 操作
| 操作 | 結果 | 失敗時の表示 |
|---|---|---|
| 向きを選ぶ | `aria-pressed` が移り、説明文が差し替わる。入力済みの名前は残る | なし |
| 名前を入力する | 最大16文字（試作版の `maxlength`）。重複を許す。空欄はスタート時に `プレイヤーN`（N は行番号）にする | なし |
| `＋ 追加` | 末尾に行を足し、新しい行の入力にフォーカスする。名前は空欄（placeholder に `プレイヤーN`） | 8人のときはボタンが `disabled` |
| `×`（削除） | その行を消す。残りの名前は行番号で振り直さない（空欄だった行だけ `プレイヤーN` が新しい行番号になる）。フォーカスは同じ位置の次の行の入力に移す。最後の行を消したら1つ前の行の入力に移す | 2人のときは `×` を出さない |
| `スタート` | 空欄を `プレイヤーN` にし、プレイ画面へ。higher は最初の1手が自由。lower はお題を引く。最初の人の検索入力にフォーカスする | なし（人数は常に2〜8人に保たれているため） |
| `← 戻る` | 入力した名前と向きを保ったままホームへ | なし |
| `やめる`（プレイ中） | 確認なしでホームへ（試作版どおり）。ゲームの状態は捨てる | なし |
| 検索ワードを入れて決定する | 「判定の順序」のとおり | ワード重複、取得中、エラーは「状態」節のとおり |
| 引き継ぎカードの `{名前} です。始める` | カードが消え、そのプレイヤーの検索入力が出る。フォーカスは検索入力に移る | なし |
| 結果画面の `もう一回` | 設定画面へ。名前と向きを残す | なし |
| 結果画面の `モード選択へ` | ホームへ | なし |

## アクセシビリティ
- すべての操作はキーボードで行える。タブ順は、上部バー、向き、名前入力（上から順）、`＋ 追加`、`スタート`。プレイ画面は、`やめる`、検索入力、決定ボタン（または引き継ぎカードのボタン）の順である。
- フォーカスの枠は試作版の `outline:3px solid var(--accent)` をそのまま使う。
- フォーカス移動：
  - スタート後は最初の人の検索入力へ
  - 引き継ぎカードが出たら、カードの主ボタンへ
  - 主ボタンを押したら、検索入力へ
  - 結果画面が出たら、勝者表示の見出し（`tabindex="-1"`）へ
  - `＋ 追加` と `×` の後は「操作」節のとおり
- 読み上げ：
  - 引き継ぎカードの結果の行（`vs-handoff-result`）と、重複メッセージは `role="status"`（`aria-live="polite"`）。色に頼らず、文で結果を伝える
  - 勝者表示は結果画面の最初の要素にし、見出しとして読ませる
  - 生存者一覧は `<ul>` とし、各項目の `aria-label` を `{名前}、手番`、`{名前}、生存`、`{名前}、脱落`、`{名前}、勝者` とする。現在の手番の項目に `aria-current="true"` を付ける
  - 向きの `.seg` は `role="group"`、各ボタンは `aria-pressed`（試作版どおり）
  - 削除ボタンは `aria-label` で誰を消すか分かるようにする
- 入力欄の `<label>` は #3 の検索入力と同じ。名前入力は `aria-label` を持つ。
- 色：脱落・手番・勝者を色だけで区別しない（記号と文字を併用する）。文字色は試作版の CSS 変数を使い、通常文字は 4.5:1 以上を保つ。脱落の `--muted` も同じ基準を満たす。ライト・ダークとも同様。
- タッチ：ボタン・入力・`×` は高さ 44px 以上を確保する。`×` は 44px 四方にする。主ボタンは幅いっぱい。
- モーション：`prefers-reduced-motion` で変化（手番の枠の切り替えなど）の動きを無効にする。そもそもアニメーションは足さない。
- 8人の生存者一覧は折り返しで並べる。画面の幅が 320px でも横スクロールを出さない。

| 引き継ぎボタン | `vs-handoff-go` |
| 履歴の脱落印 | `vs-log-out` |
| 結果画面 | `vs-result` |
| 勝者表示 | `vs-winner`（名前は `vs-winner-name`、理由は `vs-winner-reason`） |
| 手数 | `vs-result-turns` |
| もう一回／モード選択へ | `vs-again`、`vs-home` |

検索入力・決定ボタン・取得中・エラー・履歴の各行の `data-testid` は、#3 の仕様のものをそのまま使う。

## 受け入れ基準との対応
| 受け入れ基準 | 満たす要素 |
|---|---|
| 2〜8人の登録。空欄は「プレイヤーN」。名前の重複を許す | 設定画面のプレイヤー入力（`vs-player-input-{i}`、`vs-add-player`、`vs-player-remove-{i}`、`vs-start`）。人数の上限・下限は「状態」節。空欄の置き換えは「操作」節の `スタート`。重複の検査は無い |
| 向きを選べる。lower の最初のお題は試作版と同じ範囲 | `vs-dir-higher`／`vs-dir-lower`。lower のスタートで 5億〜30億（`rand(5e8,3e9)`）のお題を引き、10,000未満を切り捨てた値をカウンターに出す |
| 判定は10,000未満切り捨ての値。同値は負け。lower の最初はお題以上で負け | 「判定の順序」4、状態「引き継ぎ・脱落（負け）」。同値は higher の「前以下」、lower の「前以上」に含める |
| 負けは脱落、手番は脱落者を飛ばす | 生存者一覧（`vs-survivors`、`data-status`）、「手番の進め方」、引き継ぎカード |
| 該当なしは脱落、前の値は更新しない | 状態「引き継ぎ・脱落（該当なし）」、`vs-handoff-note`、「手番の進め方」の最後 |
| 最後の1人が勝ち。0ちょうどはその場で勝ち。結果画面に勝者 | 状態「決着・最後の1人」「決着・0ちょうど」、結果画面の勝者表示（`vs-winner`、`vs-winner-reason`） |
| 正しい再生回数と動画タイトルを #3 と同じ形で表示 | 「#3 の仕様の履歴」を再利用（履歴のみ、本仕様で形を変えない）。プレイヤー名と脱落印を足すだけ |
| 同じワードの組み合わせは2回使えない | 状態「ワード重複」、判定の順序 1 |
| 取得中・通信エラーは #3 と同じ。エラーで手番を進めない | 状態「取得中」「通信エラー」（#3 の部品を再利用）。手番は動かさず、ワードを使用済みにしない |

## 仮定
- **#3 の仕様（3.md）が未作成だったため、共通部品は想定で書いた。** 想定した内容：ホームは試作版どおり／カウンター表示は試作版の `.counter`（ラベル、大きな数字、`jp` の行）／検索入力は検索ワード入力と決定ボタン（YouTube リンクと再生回数の手入力は無い）／取得中は決定ボタンの無効化と「取得中…」の表示／エラーは文言と再試行／履歴は1行に切り捨て値、正しい再生回数、動画タイトル／結果画面は「もう一回」「モード選択へ」と履歴。3.md の部品名や `data-testid` が違う場合は、3.md を優先して読み替える。
- 引き継ぎカードを追加した。試作版には無い（試作版は決着までが1画面）。理由：脱落制では誰が脱落し、次が誰かを全員が見られる必要があり、品質（遊び心地とスマホでの操作のしやすさ）を最優先にしたため。代わりに1手ごとに1タップ増える。タップが多いと PO が感じた場合は、成功時だけカードを出さず、生存者一覧の `▶` の移動だけにする案もある（その場合は脱落時のみカードを出す）。
- 判定の順序は「負け」を先にし、その後に「0ちょうど」を見る。そのため higher の2手目以降で0を出すと負けになる（前より高くないため）。higher の最初の1手で0（10,000回未満）を出すと、受け入れ基準どおりその場で勝ちになる。この扱いが意図と違えば PO に確認が要る。
- lower の最初のお題も10,000未満を切り捨てる（範囲は試作版の `rand(5e8,3e9)` のまま、5億〜30億）。比較は切り捨て値どうし（判定値と、切り捨てたお題）で行う（PO の指摘、Sprint 2 デモ）。
- 決着の手（最後の1人になる脱落、0ちょうどの勝ち）は、引き継ぎカードを出さずにすぐ結果画面に移る。結果の理由は結果画面の `vs-winner-reason` に出す。最後の手の詳細は履歴で見られる。
- エラー時は、ワードを使用済みにしない（再試行で同じワードを使えるようにする）。#3 の扱いが違えば #3 に合わせる。
- 「やめる」は試作版どおり確認なしでホームへ戻る。確認ダイアログは #3 の仕様に従う。
- 名前は最大16文字（試作版の `maxlength`）。全角・半角の違いは名前では区別せず、そのまま表示する。
- プレイヤー名の保存（試作版の `localStorage` の `vc-prefs`）を引き継ぐ。向き（`dir`）と名前を保存し、画面の再読み込み後も残す。ゲーム中の状態は保存しない。
- 8人のとき、`＋ 追加` の無効化の理由は文字（`これ以上増やせません`）でも示す。
- ダークモードは試作版の CSS 変数のとおり。追加の色は作らない（脱落は `--muted`、成功は `--good`、負けは `--bad`）。
