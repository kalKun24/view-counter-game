# 11 UI 仕様

PBI #11「クォータ切れの表示（画面）」。共通部品は #3 の仕様（`.scrum/designs/3.md`）に任せ、この仕様は「クォータ切れ」の状態の差分だけを定める。3モード（カウントダウン、チャージ、ハイ＆ロー対戦）はすべて同じ共通の検索部品（SearchForm）を使うため、表示は SearchForm で1か所に定め、各モードは判定側を改造しない。

## 前提（サーバの応答）
応答の形は並行して #10 で決まる。この仕様は PBI #11 の記述を前提にする。

- 前提：YouTube API のクォータ切れのとき、`GET /api/views?q=` は HTTP `503` を返し、本文は `{"error":{"code":"quota_exceeded", ...}}` の形である（既存の `invalid_query` と同じ `error.code` の形を想定）。
- 画面側の判定：ステータスが `503` かつ `error.code === "quota_exceeded"` のときだけ「クォータ切れ」とする。
- 上記以外の `503`（本文が読めない、`code` が別の値）は、これまでどおり「通信失敗」（#3 の仕様の取得結果の分類）として扱い、再試行ボタンを出す。
- #10 で応答の形が変わった場合は、`classify` の判定条件だけを #10 に合わせる。この仕様の表示と操作は変わらない。

## 対象画面・コンポーネント
既存の変更。新規の画面は作らない。

| 対象 | 変更 |
|---|---|
| `web/src/api/views.ts` | 分類に `quota` を足す（`503` かつ `quota_exceeded`）。 |
| `web/src/hooks/useViewsFetch.ts` | `FetchState` に `{ kind: "quota" }` を足す。`quota` のときは `onResult` を呼ばず、使用済みにも追加しない。 |
| `web/src/components/SearchForm.tsx` | `state.kind === "quota"` のとき、検索の panel 全体を QuotaNotice に差し替える。ホームへ戻る操作のため、各モードから `onHome` を受ける。 |
| 新規部品 QuotaNotice | `.panel` の中に見出し、説明、ボタン1つ。新しい色・余白は作らない（既存の `.panel` `.btn` `.muted` を使う）。 |
| 各モード（CountdownPlay、ChargePlay、VersusPlay） | `SearchForm` に `onHome={onQuit}`（既存の「やめる」と同じ処理）を渡す以外は変更しない。判定、履歴、使用済みワード、結果画面には触れない。 |

## 構成
プレイ画面のうち、検索の panel（SearchForm）の位置だけが QuotaNotice に入れ替わる。それ以外の要素は、クォータ切れになった直前の表示のまま残す。

```
ScreenTop［やめる］［モード名（h1）］        ← そのまま
（モードごとの表示）                         ← そのまま
  カウントダウン：Counter（残り・残りターン）
  チャージ：チャージのカウンター（合計・あと何回・バー）
  ハイ＆ロー対戦：のこり N 人 / 全 M 人、生存者一覧、Counter（直前の判定値、手番のプレイヤー）
QuotaNotice（SearchForm の panel と入れ替え）
  h2「今日は遊べません」
  p 「サーバーの1日の利用上限に達しました。日をあらためて、もう一度遊んでください。」
  p.muted.small「ゲームは進んでいません。ターンは減っていません。」
  button.btn「ホームへ戻る」
panel「履歴」（WordLog。1行以上あるときだけ。そのまま）
```

- 結果画面（`ResultBanner`）にも、引き継ぎカード（ハイ＆ロー対戦）にも遷移しない。
- ボタンは「ホームへ戻る」の1つだけを QuotaNotice に置く。再試行ボタン（`retry-button`）は出さない。
- ボタンは幅いっぱいにし、高さ44px以上（#3 の仕様のタッチ要件どおり）。
- ScreenTop の「やめる」は、共通の上段として残す（PO に示す事項 1）。

## 状態
#3 の仕様の「検索フォーム（プレイ中）」の状態表に、次の行を足す。

| 状態 | data-state | 表示 | 遷移条件 |
|---|---|---|---|
| クォータ切れ | quota | 検索の panel が QuotaNotice に入れ替わる。入力欄、決定ボタン、再試行ボタンは存在しない。カウンター、生存者一覧、履歴は直前のまま。 | 取得中に `503` かつ `quota_exceeded` を受けた。 |

この状態から他の状態へは戻らない（検索を再開する操作が存在しない）。抜ける方法は「ホームへ戻る」または「やめる」だけで、どちらもホームへ移る。

### モードごとの扱い
| モード | クォータ切れのときの表示 | ゲームの状態 | 抜けたあと |
|---|---|---|---|
| カウントダウン | QuotaNotice。Counter は直前の残りと残りターンのまま。 | 残り、履歴、使用済みワード、ターンを変えない。`GAME OVER` にも `CLEAR` にもしない。 | ホームへ。ゲームの状態は捨てる（「やめる」と同じ）。 |
| チャージ | QuotaNotice。合計、あと何回、バー、残りターンは直前のまま。 | 合計、履歴、使用済みワード、ターンを変えない。`GAME OVER` にも `CLEAR` にもしない。バーストやターン切れの判定もしない。 | 同上。 |
| ハイ＆ロー対戦 | QuotaNotice。生存者一覧、手番の表示、直前の判定値は直前のまま。引き継ぎカードは出さない。 | 当該プレイヤーを脱落させない。手番は動かさず、生存者数、前の値、履歴、使用済みワードを変えない。結果画面（`GAME SET`）にも勝者にも遷移しない。 | 同上。対戦全体が中断される（1人分の問題ではなく、全員が検索できないため）。 |

- ハイ＆ロー対戦で脱落扱いにしない理由：該当なし（`found:false`）は「ルールとして脱落」だが、クォータ切れはサーバ側の事情でプレイヤーの手とは関係がない。脱落させると勝敗が遊び手の責任でなく決まる。
- クォータ切れの状態は画面側に記憶しない。ホームから新しくゲームを始めて検索したとき、まだ切れていれば同じ表示になり、回復していれば通常どおり遊べる。

## 数字の表示規則（T2-1）
該当なし。この PBI は画面に出る数字を増やさない（QuotaNotice に数字を出さない。クォータの残量、復旧の時刻、日付も出さない）。クォータ切れの時点で画面に残っているお題、残り、合計、上限、目標、判定値、履歴の切り捨て値と実際の再生回数は、#3・#4・#5 の仕様の表示規則のまま変更しない。

PO の言葉（「判定としては10,000未満は切り捨て…正しい数字も注釈で出しておく」「お題の数字も、10,000未満は切り捨てようよ」）に反する数字はこの仕様に無い。

## 操作
| 操作 | 結果 | 失敗時の表示 |
|---|---|---|
| 検索ワードを入れて決定し、`503` と `quota_exceeded` を受ける | 状態「クォータ切れ」へ。QuotaNotice を出し、フォーカスを見出しへ移す。入力は破棄する（SearchForm ごと外れる）。 | なし |
| 「ホームへ戻る」を押す | ホームへ。ゲームの状態（お題、履歴、使用済み、手番）を破棄する。確認はしない。 | なし |
| 「やめる」（ScreenTop）を押す | ホームへ（#3 の仕様のまま）。 | なし |
| 取得中に「やめる」を押す | リクエストを中止し、結果を捨てる（#3 の仕様のまま）。クォータ切れの応答が届いていても表示しない。 | なし |
| 再試行 | 操作が存在しない（ボタンを出さない）。 | なし |

## 文言
- 見出し（h2）：今日は遊べません
- 説明：サーバーの1日の利用上限に達しました。日をあらためて、もう一度遊んでください。
- 補足（`.muted.small`）：ゲームは進んでいません。ターンは減っていません。
- ボタン：ホームへ戻る
- 読み上げ用（見出しにフォーカスを移すため、追加の文言は無し）。
- 「壊れていると誤解しない」ために、「エラー」「失敗」「通信」の語を使わない（通信失敗の文言と区別する）。
- 「明日」とは書かない（復旧の時刻が日本時間の日付と一致しないため）。

## アクセシビリティ
- フォーカス：QuotaNotice が出たら、見出し（h2、`tabindex="-1"`）にフォーカスを移す。検索入力が外れてフォーカスを失わないため。見出しの次の Tab で「ホームへ戻る」に着く。
- 読み上げ：フォーカス移動により、見出しが読まれる。続けて説明を読めるよう、見出しと説明は `<section aria-labelledby>` にまとめる。`role="alert"` は重ねない（二重に読まれるため）。
- キーボード：ボタンは `<button type="button">` で、Enter / Space で押せる。タブ順は、やめる、見出し（プログラムからのフォーカスのみ）、ホームへ戻る。
- 色：文言で状態を伝える（色だけに頼らない）。新しい色は使わず、`.panel` `.btn` `.muted` のトークンのまま。コントラストは #3 の仕様のとおり（`.btn` はライトで `--accent-strong`）。
- タッチ：ボタンは高さ44px以上。幅いっぱい。
- 動き：アニメーションを足さない。
- 360px 幅：panel は1カラムで、固定幅を置かない。横スクロールを出さない。

## data-testid
| testid | 要素 |
|---|---|
| `quota-notice` | QuotaNotice 全体（section） |
| `quota-title` | 見出し（h2） |
| `quota-message` | 説明 |
| `quota-home` | 「ホームへ戻る」 |

検索入力（`search-input`）、決定（`search-submit`）、`search-status`、`retry-button` は、クォータ切れの状態では存在しないこと。`result-heading` も存在しないこと。カウンター、履歴、生存者一覧の testid は #3・#4・#5 のものをそのまま使い、値が直前から変わらないことを確かめる。

## 受け入れ基準との対応
| 受け入れ基準 | 満たす要素 |
|---|---|
| API が `503` と `quota_exceeded` を返したとき、画面に「今日は遊べない」旨を表示する。 | 状態「クォータ切れ」、QuotaNotice の見出し「今日は遊べません」と説明、`quota-notice` `quota-title` `quota-message`。 |
| `GAME OVER` や `CLEAR` の結果にはならず、ターンと使用済みワードも消費しない。 | 「モードごとの扱い」の「ゲームの状態」列（3モードとも）。`onResult` を呼ばない。`result-heading` が存在しない。ハイ＆ロー対戦は脱落扱いにしない。 |
| 再試行ボタンは出さず、「ホームへ戻る」ボタンだけを出す。 | QuotaNotice のボタンは「ホームへ戻る」（`quota-home`）のみ。`retry-button` が存在しない。 |

| 3.md の共通部品の区分（SearchForm、FetchStatus は共通でモードごとに差し替えない） | QuotaNotice を SearchForm の中に置き、モード固有の変更を作らない。 |
| 4.md 状態「通信エラー」：API が 400・502・通信失敗を返す | クォータ切れ（503 `quota_exceeded`）は別の状態として追加する。通信エラーの記述は変えない。 |
| 5.md 状態「通信エラー」：取得が 400 / 502 で終わる。手番も使用済みワードも変えない | 同上。クォータ切れでも手番、使用済み、履歴を変えない。5.md の「引き継ぎ・脱落」とも別の状態で、脱落にしない。 |

## 仮定
- 応答の形は「前提（サーバの応答）」のとおり。#10 の確定内容と違えば、判定条件だけを直す。
- QuotaNotice は SearchForm の panel と入れ替え、プレイ画面のカウンターと履歴は残す。結果画面への遷移や別画面への切替は、受け入れ基準の「結果にならない」と、状態が進んでいないことの視認を優先して採らなかった。
- クォータ切れの表示は画面側に記憶しない（リロードでホームに戻る #3 の仕様と整合し、復旧したらすぐ遊べる）。
- 「ホームへ戻る」はゲームの状態を破棄する（「やめる」と同じ）。クォータ切れ中は検索を再開できないため、途中再開の仕組みは作らない。
- 429（#7 の回数制限）はこの仕様の範囲外とする。#7 で扱う。
- デモ用モックの `quota` 入力で `503` と `quota_exceeded` を返す動作は、#10 の範囲とする。

## PO に示す事項
根拠の無い判断を次に示す。

1. ScreenTop の「やめる」を残すかどうか。受け入れ基準は「ホームへ戻るボタンだけを出す」とある。この仕様は、共通の上段（ScreenTop）を3画面で揃えるため「やめる」を残し、QuotaNotice の中のボタンを「ホームへ戻る」の1つにした。ホームへ戻る操作が画面に2つ見える。QuotaNotice 表示中は「やめる」も隠す案もある。どちらにするかを PO に確認したい。
2. 文言の「サーバーの1日の利用上限」。デッキには「今日は遊べない」としか書かれていない。理由（YouTube の利用上限）を遊び手に見せるかどうか、また「日をあらためて」の言い回しでよいかを確認したい。復旧の時刻は書いていない。
3. ハイ＆ロー対戦で、クォータ切れのとき対戦全体を中断してホームに戻す（途中の勝敗は残さない）扱い。デッキに該当する記述が無い。
