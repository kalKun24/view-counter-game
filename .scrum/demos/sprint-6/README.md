# Sprint 6 のデモ
## ゴール
PO が、上限に達したとき、画面とヘッダの両方で「あと何時間で遊べるか」が分かること、キャッシュの期限が既定で6時間になり、24時間を超える設定や空の設定では起動しないことを、本物の API を呼ばずに確かめられる。

## 動かし方
```
bash .scrum/demos/sprint-6/demo.sh
```
- 前提：Go、curl、python3、Node 22 以上、Chrome（または Chromium）が使えること。`web/node_modules` があること（無ければ `cd web && npm ci`）。所要時間は数分（場面 4 のテスト20回が大半を占める）。
- 動かすコードを変える場合は、第1引数にディレクトリを渡す。第2引数 `--rehearse` は、最後で Enter を待たずに終わる。
- ネットワークは使わない。サーバは `USE_MOCK=1` で動かし、本物の YouTube Data API は呼ばない（`YOUTUBE_API_KEY` は環境から外す。`CACHE_TTL` などの設定も外し、場面ごとに必要なものだけを渡す）。
- サーバと画面の開発サーバ（Vite）は、空いているポートで動かす（8080 は使わない）。宛先は 127.0.0.1 の自分のサーバだけである。
- 場面ごとに「確認 OK／NG」を表示する。終了コードは NG の数で決まる（0 件なら 0）。
- 全場面のあと、スクリプトは画面の URL（`http://127.0.0.1:<ポート>/`、実行時に表示）を表示して待つ。このサーバは場面 2 の抑制中のままなので、どのワードで検索しても「いまは遊べません」の画面になる。Enter で終了する（サーバを止めて一時ファイルを消す）。

### 場面 2 の画面の確かめ方
画面の「約N時間」は `Retry-After` から決まり、3600 ちょうどなら「約1時間」、3600 未満（3599 など）は「約60分」や「約59分」になる（UI 仕様 `.scrum/designs/32.md` の変換規則。切り上げ前の秒数で判定する）。抑制が始まってから1秒以上たつと残りは 3599 以下になるので、同じ「約1時間」を期待すると結果がぶれる。そこで文言だけに頼らず、`quota-notice` の `data-retry-after` の値と文言の対応を確かめる。

1. 新しいサーバで、最初にブラウザから `quota` を検索する。上流の最初の応答なので `Retry-After` は 3600 で固定になる。セレクタ `[data-testid=quota-notice][data-retry-after="3600"] [data-testid=quota-message]` の文言が「あと約1時間で、もう一度遊べます。」であることを確かめる（値と文言を同じセレクタで結ぶ）。
2. 1秒以上おいてホームへ戻り、新しい対戦で別のワード（`delta`）を検索する。抑制中なので 503 が返り、`data-retry-after` は 3600 ではなく 3500 台になる。`[data-testid=quota-notice][data-retry-after^="35"] [data-testid=quota-message]` の文言が「あと約60分で、もう一度遊べます。」であることを確かめる。
3. どちらも見出し「いまは遊べません」、注記、再試行ボタンが無いこと（検索入力も出ない）を確かめ、スクリーンショット（`quota-first-3600`、`quota-second-suppressed`）を残す。

- 台本は curl で `quota` を送った同じサーバで検索する流れだが、画面用には新しいサーバを使った。同じサーバだと最初の画面が必ず 3599 以下（約60分）になり、「約1時間」の確認ができないためである。curl の部分（`quota` が 3600、別のワードが 3600 以下）は台本のとおり同じサーバで確かめる。
- 3500 台の確認は、抑制が始まってから約60秒以内に検索する前提である（スクリプトの流れでは数秒）。60秒を超えると「約59分」になり、確認が外れる。

### #29 のテストを壊すと fail する表（担当の報告）
置き換えたテストが、壊したときに fail することを担当が確かめた（壊した変更はコミットしていない。デモでは壊す実演はしない）。

| 壊した箇所 | fail したテスト |
|---|---|
| `useViewsFetch.ts` の unmount 時の `abort` を外す（`ctrl.signal.aborted ||` の判定も外す） | 3 件：`App.test.tsx`「やめるで取得を中止し、あとから届いた結果は捨てる」、`quota.test.tsx`「取得中に「やめる」を押したら、届いたクォータ切れの応答は表示しない」、`throttle.test.tsx`「取得中に「やめる」を押したら、届いた制限の応答は表示しない」 |
| `views.ts` の `setTimeout(..., timeoutMs)` を `timeoutMs - 1`（1ms 短く）にする | 1 件：`views.test.ts`「15秒で応答がなければ error(timeout)。cancelled とは区別する」 |

- 注意：`ctrl.signal.aborted` の判定だけを外しても pass する（`cancelled` の判定で止まる二重の防御のため）。
- 20回の実行は、4ファイルを統合ブランチで実行した件数である。担当の報告では、並行するコマンドと重なった1回目の20回で2回 fail した（原因は未特定で、#31 で扱う）。デモは他のコマンドと並行せずに20回を順に実行する。
