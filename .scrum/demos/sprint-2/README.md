# Sprint 2 のデモ
## 2回目（見せ直し）。1回目の指摘と対応
- 指摘（PO）：「お代の数字も、10,000未満は切り捨てようよ。　出してる意味なくない？」
- 対応：カウントダウンのお題、チャージの目標と上限、対戦「前より低く」の最初のお題を、10,000未満を切り捨てた値にした。表示は「◯億◯万」で終わり、1〜9999 の端数が付かない。
- 見せ直しの場面は 8a〜8c である。1〜7 は1回目と同じ内容で、そのまま残してある。

## ゴール
PO がスマホ幅のブラウザで、モックを相手に、カウントダウン・チャージ・ハイ＆ロー対戦の3モードを最後まで遊べる。判定には10,000未満を切り捨てた値を使い、画面には正しい再生回数も注釈として出る。

## 動かし方
```
bash .scrum/demos/sprint-2/demo.sh
```
- 前提：Go、Node 22 以上、Chrome（または Chromium）、python3、curl が使えること。`web/` で `npm ci` が済んでいること。所要時間は約 1 分（`slow` の待ちを含む）。
- Go サーバ（`USE_MOCK=1`）と Vite の開発サーバを、空いているポートで起動する。本物の YouTube Data API は呼ばない。接続先は 127.0.0.1 だけである。
- まず、ヘッドレスの Chrome（幅 390px）が台本の場面 1〜7、8a〜8c を自動で操作して確認し、スクリーンショットを一時ディレクトリに残す（出力先は実行時に表示される）。
- 続いて、表示された URL（例：`http://127.0.0.1:<ポート>/`）を開くと、自分で触れる。スマホ幅で見るには、ブラウザの開発者ツールで幅を 390px にする。終わるときは、ターミナルで Enter を押す（Go と Vite の両方が止まる）。
- 動かすコードを変える場合は、第1引数にディレクトリを渡す。`--rehearse` を第2引数に付けると、待たずに自動確認だけで終わる。
- 最後に、補足として `npm test`（web）と `go test ./...`（server）を実行する。

## モックのワード
画面の検索ワードに次を入れる（スペース区切りで組み合わせてよい）。
- `n<数字>`：その数字を再生回数にする（例：`n150000000`）。`n5000` は切り捨てて 0 になる。
- `nomatch`：該当なし。`slow`：約 3 秒遅れる。`error`：通信エラー（502）。
- それ以外のワード：ワードから決まる固定の値（1,000〜約 1 億）。
- 同じワードの組み合わせは使えないので、`n100000000 a`、`n100000000 b` のようにワードを足して変える。
