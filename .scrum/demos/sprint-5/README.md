# Sprint 5 のデモ
## ゴール
PO が、YouTube の1日のユニットの上限に達すると上流を呼ばずに 503 を返すこと、quotaExceeded のあと1時間は上流を呼ばないこと、脆弱性の検出が注記も含めて無くなったこと、連打されたときに画面が「操作が多すぎます」と案内して状態を変えないことを、本物の API を呼ばずに確かめられる。

## 動かし方
```
bash .scrum/demos/sprint-5/demo.sh
```
- 前提：Go、Docker、make、curl、python3、Node 22 以上、Chrome（または Chromium）が使えること。`web/node_modules` があること（無ければ `cd web && npm ci`）。所要時間は、Docker のイメージが取得済みなら数分以内（初回は取得の分だけ延びる）。
- 動かすコードを変える場合は、第1引数にディレクトリを渡す。第2引数 `--rehearse` は、最後で Enter を待たずに終わる。
- ネットワークを使うのは、場面 3 の `make vuln`（脆弱性データベース）だけである。サーバは `USE_MOCK=1` で動かし、本物の YouTube Data API は呼ばない（`YOUTUBE_API_KEY` は環境から外す）。
- サーバと画面の開発サーバ（Vite）は、空いているポートで動かす（8080 は使わない）。宛先は 127.0.0.1 の自分のサーバだけである。
- 場面ごとに「確認 OK／NG」を表示する。終了コードは NG の数で決まる（0 件なら 0）。
- 上流を呼んだかどうかは、次の 2 つで見る。(1) モックは通常のワードに 200 を返すので、503 が返れば上流（モック）に届いていない。(2) ログの「youtube quota exceeded」（上流が返した quotaExceeded）が 1 回のままである。上流を呼ばなかった要求の行は Debug のため、既定のログには出ない。
- 全場面のあと、スクリプトは画面の URL（`http://127.0.0.1:<ポート>/`、実行時に表示）を表示して待つ。このサーバは `RATE_LIMIT=2` なので、ブラウザで3回続けて検索すると制限の表示になる。Enter で終了する（サーバを止めて一時ファイルを消す）。

## 台本
| # | PO の操作 | 期待する結果 | PBI |
|---|---|---|---|
| 1 | 上限を外れ2回分（`DAILY_UNIT_LIMIT=202`）に下げてモックで起動し、違うワードで `curl` を3回送る。そのあと1回目のワードをもう一度送る。 | 1・2回目は 200、3回目は 503 `quota_exceeded`。ログに「daily unit limit reached」が 1 回出る。1回目のワードの再送はキャッシュから 200。 | #26 |
